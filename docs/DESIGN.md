# v11 设计与验证口径

## 与v10的根本区别

v10在已有数值/对称规则内做深度优先枚举，目标是尽量保留原有枚举范围。v11默认改成目标引导的有界beam搜索：每层只延续一批状态，候选先粗评、实际落子后精评，再保留高分和一部分多样性状态；多个worker用不同随机流独立探索，按预算重启。

这不是把剪枝后的节点少当成性能提升。验收必须比较同一个真实有解输入的：

- 固定预算内是否找到有效构造，以及多个seed的成功率；
- 首次达到目标用时与返回E；
- 内存和取消响应；
- v10与v11搜不到时各自的状态，而不是把启发式失败叫EXHAUSTED。

## 不会改变的几何规则

- 新元素由已知两点构造；目标坐标仅打分，不能成为落子端点或免费圆心。
- 初始线段/射线仍有界；想用支持直线必须付费作出。
- 保留EPS、点插入次序、交点计算与严格浮点编译选项。
- 目标匹配仍为浮点几何，所以找到解不等于符号级证明，重要构造需要独立回放。

## 明确的折衷

- beam和branch上限丢弃路径，不能证明没有解/最短E。
- 随机多启动缓解局部偏好，不保证找到任何指定构造。
- 几何距离只是弱特征，不是唯一排序；结构特征和多样性更重要。
- 旧v10尾搜作为限时找解助手，局部失败不用于证明或永久排除状态。
- 启发式没有可信的整树覆盖百分比和搜完ETA，因此界面明确unavailable。

## 保留完整枚举路径

`--search=exhaustive`切换到独立保留的v10逻辑，用于回归和需要旧枚举行为的任务。两个引擎共享输入及结果报告，不混淆停止状态。
